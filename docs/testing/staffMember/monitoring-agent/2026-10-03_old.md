## Investigation and changes

- Observed failure: initial restore selected vulnerable `SQLitePCLRaw.lib.e_sqlite3` 2.1.11.
- Confirmed cause and evidence: transitive dependency from Microsoft.Data.Sqlite 10.0.0; NuGet audit emitted NU1903.
- Changed result: native library explicitly pinned to patched 2.1.13; subsequent vulnerability audit reports none for the agent project.
- First-run debugger evidence showed an unhandled `DirectoryNotFoundException` when the executable was started before registration. Startup now validates both bootstrap files and their protected contents, displays setup guidance, and exits cleanly instead of exposing a filesystem exception.
- Swagger generation failed because Swashbuckle rejects an `IFormFile` action parameter explicitly decorated with `[FromForm]`. ASP.NET Core already infers the file as multipart form data, so the redundant attribute was removed without changing the request field name or runtime command flow.
- Existing `EmployeeDeviceEnrollment` was confirmed to be biometric/card attendance hardware and was not reused or changed.
- Changed files: separate domain entities, repository/EF mappings, additive SQL, CQRS handlers, controller, storage adapter, Windows agent project, tests and handoff documentation.
- Tests establish compile-time contracts, authorization attributes, policy validation and filesystem key isolation. They do not establish database migration, JWT permission data, real screenshot capture, API transport, installer startup or deployed storage.
