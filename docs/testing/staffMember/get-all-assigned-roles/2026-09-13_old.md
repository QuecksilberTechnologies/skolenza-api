## Investigation and changes

- Confirmed cause: the existing Employee-list DTO and repository projection did
  not load `UserRole`/`Role` data.
- Change: one page-batched role query now applies tenant, active and soft-delete
  filters, collapses duplicate Role IDs and populates `assignedRoles`.
- Schema fact: `Role` has no separate RoleCode column. `code` is therefore derived
  from `RoleName` using uppercase underscore formatting; `type` derives from
  `IsSystemDefault`.
- The executed contract test establishes JSON property names and empty-array
  behavior. It does not establish deployed data accuracy.
