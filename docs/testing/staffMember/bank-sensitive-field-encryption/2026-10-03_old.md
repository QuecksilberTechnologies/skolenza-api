## Investigation and changes

- Before the change, Create and Update persisted all three sensitive values as plaintext; Get returned the same plaintext and Angular performed display masking.
- `IEncryptionService` was already injected into the Bank handlers but unused.
- The implementation now calls that existing tenant-key AES service on Create/Update and decrypts only during authenticated Get response projection.
- No new encryption/hash algorithm, key store, permission rule, endpoint or Angular behavior was introduced.
- Account-number sorting remains a ciphertext database sort; no new plaintext lookup/hash column was authorized or added.
- The first Render idempotency rerun exposed a test-only defect: the verifier uppercased the IFSC ciphertext before decrypting it. That rerun failed and its transaction rolled back. The verifier was corrected to normalize plaintext only; the following Render rerun passed for both ciphertext rows, confirming the committed data remained valid.
