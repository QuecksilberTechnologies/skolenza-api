## Investigation and changes

- Existing reads already resolve `Employee.CountryId -> CountryIdentityRule ->
  IdentityCategoryDocument`; save validation rejects documents not configured
  for the employee country.
- Observed defect: `CreateAsync` added tracked records but the handler committed
  the database transaction without calling `SaveChangesAsync`. A success
  response could therefore be returned without an inserted identity row.
- Fix: save changes now completes before transaction commit.
- Identity completion is calculated from each configured catalogue row. The
  response envelope averages those row values, so one saved document out of
  two configured documents reports 50%.
- The Angular identity form now renders the API catalogue rather than a fixed
  India-only field list. Required state comes from `isMandatory`; existing
  multipart request keys and endpoint were preserved.
- Root cause of the selected-employee India result: the profile URL carried an
  encoded `employeeId`, but `EmployeeIdentityInfo` omitted it from
  `GET /Employee/Sensitive/get`. The handler therefore correctly fell back to
  the logged-in India employee. The request interface/component now forward
  the selected encoded employee ID. The API continues to ignore the legacy
  country hint for eligibility and reads the target employee's persisted
  `CountryId` before querying `CountryIdentityRule`.
- The country catalogue contains a UK `NINO` master/rule. This is seed data,
  not conditional Angular or handler logic.
- The employee list now uses its existing `countryCode` and `nationality`
  response fields to show an ISO code and flag. Unknown or non-ISO values do
  not render a broken flag image.
- Seed change: Passport is an optional global baseline. Country-specific
  documents remain data-driven and are not hardcoded in handlers.
- Statutory jurisdiction is intentionally separate: it will resolve from the
  effective primary employment location, not identity/nationality country.
