## Expected catalogue options — seed review only

Historical source (now consolidated): [employee identity catalogue](../../../../database-scripts/production-seed/05-dependent-master/001-employee-identity-catalog.sql).

| Country | Document code | Document name | New rule default |
| --- | --- | --- | --- |
| China (`CN`/`CHN`) | `NATIONAL_ID_CN` | Resident Identity Card | `IsMandatory=false` |
| United States (`US`/`USA`) | `SSN` | Social Security Number | `IsMandatory=false` |

These are **seed expectations, not options returned successfully by the live
API**. The seed creates missing document catalogue entries and country mappings
only where a matching active Country exists. It does not insert Country rows.
It preserves existing configured rules, including mandatory flags. Other
configured active mappings can also affect the actual returned options.

On a successful lookup the response data is an array containing
`identityCategoryDocumentId`, `documentCode`, `documentName`, `countryCode`,
`countryName`, `isMandatory` and optional saved identity information. An option
without a saved EmployeeIdentity can have null employee/identity IDs and values.
Do not treat an available option as proof that a document was uploaded.

## Failure investigation and implemented fix

- Confirmed live symptom: China identity GET returned HTTP 500.
- Reviewed old code called PostgreSQL `GetEmployeeIdentityByCountryRule`.
  Its definition was found in `skolenza.application/DTOS/SPFunctions.txt`, not
  in an executable migration/seed found during that review. A missing or
  mismatched deployed function is a **suspected cause**; a server exception or
  direct target-function inspection was not captured to prove it caused this 500.
- Commit `05390640` removes that function dependency from
  `StoreProcedureRepository.GetIdentityRecordAsync`, using an EF country-rule
  query. Existing handler authorization remains in place.
- A confirmed projection defect copied `EffectiveFrom` into `EffectiveTo`.
  The fix uses the correct end date and maps the internal date fields as
  `DateOnly?`, retaining the response's nullable DateTime fields.
- Passing local tests establishes the recorded local assertions only. It does
  not establish deployed query execution, country catalogue seeding, or delivery
  of the expected options.
