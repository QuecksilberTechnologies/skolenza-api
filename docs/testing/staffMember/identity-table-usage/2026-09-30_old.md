# Employee identity table usage audit — 2026-09-30

## Scope and status

- Scenario ID: EMP-IDENTITY-TABLE-USAGE-2026-09-30
- Requested outcome: identify identity tables used by the country-driven
  employee identity flow and remove tables proven unused.
- Environment: current source plus read-only metadata/count queries against the
  configured production PostgreSQL database `workforcedb_34hi_duis`.
- Overall status: PASS for the audit. No table was deleted because every
  identity table participates in the current flow.

## Production inventory

| Table | Rows | Current responsibility | Code path | Decision |
| --- | ---: | --- | --- | --- |
| `IdentityCategory` | 4 | Groups document masters, such as tax, social-security, voter and government identity | `IdentityCategoryDocument.IdentityCategoryId`; GET filters active category | KEEP |
| `IdentityCategoryDocument` | 12 | Master definitions for Aadhaar, PAN, Passport, NINO and other document types | GET projection, create request document ID, create validation | KEEP |
| `CountryIdentityRule` | 260 | Data-driven country-to-document eligibility and mandatory flag | GET catalogue filter and create-time allow-list validation | KEEP |
| `EmployeeIdentity` | 0 | Stores an employee's entered identity value, upload metadata, verification and effective dates | GET left join and create persistence | KEEP |

An empty `EmployeeIdentity` table is expected before employees save identity
values. It is the transaction table for this feature and is not unused.

## Foreign-key evidence

1. `IdentityCategoryDocument.IdentityCategoryId -> IdentityCategory.Id`
2. `CountryIdentityRule.CountryId -> Country.Id`
3. `CountryIdentityRule.IdentityCategoryDocumentId -> IdentityCategoryDocument.Id`
4. `EmployeeIdentity.EmployeeId -> Employee.Id`
5. `EmployeeIdentity.IdentityCategoryDocumentId -> IdentityCategoryDocument.Id`

## Request flow

### Read

`GET /api/Employee/Sensitive/get` decodes the selected employee ID, reads that
employee's persisted `CountryId`, queries active `CountryIdentityRule` rows,
joins `IdentityCategoryDocument` and `IdentityCategory`, and left-joins any
saved `EmployeeIdentity` rows. Angular renders the returned catalogue rows.

### Create

`POST /api/Employee/Sensitive/create` resolves the target employee, validates
each submitted document against `CountryIdentityRule` and the active document
and category masters, then inserts into `EmployeeIdentity`.

## Unused database objects found

The database still contains PostgreSQL functions
`GetCountryIdentityDocument` and `GetEmployeeIdentityByCountryRule`. Repository
search found their definitions only in `skolenza.application/DTOS/SPFunctions.txt`
and historical documentation. The current runtime uses EF queries instead.
These are legacy functions, not tables, and were not dropped by this audit.

Removal was subsequently completed against local database
`workforcedb_local_20260928`: both exact signatures had zero external
dependencies, were dropped without `CASCADE`, and their definition blocks were
removed from `SPFunctions.txt`. The suspended Render database was not changed.
The controlled flow and current status are documented in
[`EMPLOYEE_COUNTRY_IDENTITY.md`](../../../UIdeveloperDoc/EMPLOYEE_COUNTRY_IDENTITY.md)
and the [cleanup test report](../legacy-identity-function-removal/2026-09-30.md).

## Verification and deletion result

- Production metadata query found exactly four identity-named base tables.
- Production FK query found five active dependencies across those tables.
- Source review confirmed current reads and writes for every table.
- Deleted tables: **none**.
- Deleted functions: **2 locally and from project definitions**; Render cleanup
  remains pending while its PostgreSQL service is suspended.
- Skipped/blocked tests: none; this was a read-only schema/code audit rather
  than a behavior change.
