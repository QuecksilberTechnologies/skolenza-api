## Investigation and changes

- Root cause: `EmployeeWorkPatternResponseDTO` omitted employee identity and repository reads did not
  load the employee through the parent arrangement. The UI therefore rendered its null fallback.
- The response now contains tenant-salt encoded `employeeId` and mapped `employeeName` for create,
  update, status, get-by-id and paged-list responses.
- A pattern remains one recurring weekday under a dated work arrangement; it does not own dates.
