# Database: local to Render full data synchronization — 2026-10-13

## Scope and status

- Scenario ID: DB-LOCAL-RENDER-FULL-001
- User-requested behavior: replace the Render `skolenza` schema with the complete local
  `SkolenzaDB` schema and data so deployed testing uses the same state.
- Overall status: PASS.
- Source: configured local PostgreSQL `SkolenzaDB`, schema `skolenza`.
- Target: configured Render PostgreSQL database, schema `skolenza`.
- Credentials, bearer tokens and personal documents are not recorded.

## Procedure

1. Read both connection strings at runtime from the existing Development and Production settings.
2. Compared pre-sync object and key-row counts. Local contained 185 tables, 4 institutions and
   5 staff members; Render contained 175 tables, 2 institutions and 2 staff members.
3. Exported the complete local `skolenza` schema and data with PostgreSQL 18 `pg_dump`, excluding
   ownership and privileges.
4. Replaced the Render schema inside one `psql --single-transaction` execution. The transaction
   dropped the target schema, recreated the local `btree_gist` extension in that schema, restored
   every object and row, reset sequences and created constraints/indexes.
5. Compared exact per-table row counts and schema-object counts, then exercised the deployed API.

The first restore attempt did not include the schema-owned `btree_gist` extension and failed while
creating a GiST index. Because it was executed with `ON_ERROR_STOP` and `--single-transaction`, the
whole attempt rolled back and Render remained unchanged. The corrected atomic restore included the
extension and committed successfully.
