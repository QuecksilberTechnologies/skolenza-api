## Investigation and changes

- Observed failure: pgAdmin restore attempts used `--clean` before the schema existed and later attempted to create the source database name. Both attempts exited 1 before a valid full restore.
- Confirmed cause and evidence: pgAdmin Process Watcher showed `schema "skolenza" does not exist` during cleanup and later attempted `CREATE DATABASE workforcedb_local_20260928`.
- During the command-line restore, the data phase completed but the verbose process stalled before post-data completion. At that point data counts were complete but foreign-key count was zero.
- Resolution: stop the stalled process, generate the archive's post-data SQL locally, then apply it with `psql` and `ON_ERROR_STOP=1`. The command exited 0.
- Changed files and commit: documentation only; no application code or business logic changed in this scenario.
- Verification establishes database content and relational objects on the replacement Render database. It does not establish API startup, authenticated UI flows or a new deployed API build.
