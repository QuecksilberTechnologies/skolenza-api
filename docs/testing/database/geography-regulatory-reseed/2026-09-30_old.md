## Investigation and changes

- Observed failure: the first identity seed attempt stopped on duplicate primary
  key `IdentityCategory.Id = 1`.
- Confirmed cause and evidence: the restored database sequence lagged behind the
  table maximum. The failed transaction rolled back completely.
- Resolution: the existing sequence-synchronization logic from the same seed
  bundle was executed before rerunning the identity seed. The rerun committed
  one category, six documents and six country mappings as designed.
- Changed files: this scenario report and the test index only; no application or
  seed business logic changed.
- The regulatory script reported cascades to rule/payroll-dependent tables. The
  direct dependent tables were verified empty before execution. After execution,
  `SalaryComponentMaster`, `EmployeeStatutoryAccount`, `PayrollEmployeeDetail`
  and `SalaryStructureDetail` are all zero.
