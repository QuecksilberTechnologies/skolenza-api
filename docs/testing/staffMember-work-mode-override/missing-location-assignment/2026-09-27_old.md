# Work-mode override: missing location assignment — 2026-09-27

## Scope and status

- Scenario ID: EWO-LOC-001
- Environment: localhost UI backed by the configured development database.
- Result: reproduced and root cause confirmed; no code or data changed.

## Sanitized input and API sequence

The UI attempted to create a one-day active override for the test employee on 28/09/2026,
using Field mode, the employee's active WFH arrangement, and the Railway-Client location.
The create request returned the location-assignment validation error shown by the UI.

## Expected versus actual

| Check | Expected | Actual | Status |
| --- | --- | --- | --- |
| Employee eligible | Active, tenant-owned employee | Active and not soft-deleted | PASS |
| Arrangement covers date | Active arrangement covering 28/09/2026 | Active open-ended arrangement from 27/09/2026 | PASS |
| Location type | Field accepts Client Site or Project Site | Railway-Client is Client Site | PASS |
| Attendance policy | Physical assigned location is permitted | Assigned Locations scope; web/mobile/manual enabled | PASS |
| Employee location assignment | Active, attendance-allowed Railway-Client assignment covering 28/09/2026 | No matching assignment row exists | FAIL / EXPECTED REJECTION |

The employee has one active, attendance-allowed, open-ended primary assignment for a different
office location. That record cannot authorize attendance at Railway-Client.

## Evidence and conclusion

The validator calls `HasCoveringAttendanceLocationAssignmentAsync` before policy validation. The
query requires the same tenant, employee and location, active and non-soft-deleted state,
attendance permission, and an effective window covering the complete override period. The database
contains no employee/location row for Railway-Client, so the displayed error is correct.

The UI location dropdown currently exposes a tenant location that is not eligible for the selected
employee and override dates. This is a UI flow gap: the list should be filtered to covering employee
assignments, or clearly label unavailable locations and direct the administrator to create the
assignment first.

## Persistence and cleanup

or deleted. No cleanup is required.
