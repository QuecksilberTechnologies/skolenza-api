# Angular, API and SQL naming alignment — 2026-10-11

## Environment and scope

- Local Windows workspace; Angular development build and .NET Release build.
- Local `SkolenzaDB`, schema `skolenza`.
- Scope: Angular physical/symbol naming, Angular–API routes, current deployment/production seed SQL, and regression checks.

## Changes verified

- Angular active source paths and content contain no `Tenant` or `Employee` legacy names.
- Angular folders/files use institution, campus, staff member, and staff employment type naming.
- Component selectors and route slugs use kebab-case.
- Removed self-redirect loops for campuses, institution, and staff employment types.
- Staff statistics URL now matches `/api/StatData/Dashboard/StaffMembers/Statistics`.
- Staff member code-pattern and device DDL routes use kebab-case in API and Angular.
- Known unimplemented permission, asset-assignment, and insurance calls are intercepted with an explicit unavailable response instead of reaching a 404.
- Current production seed, deployment bootstrap, and complete seed SQL use canonical Institution/StaffMember identifiers. Historical physical-rename and rollback migrations retain source names because those identifiers are their migration input.
- The separate `SkolenzaDb` SQL workspace is synchronized with the canonical API script set; retired legacy copies were moved into the recoverable migration backup.
- Institution detail contracts now use `Campuses` and `TotalCampuses` across Angular, API DTOs/repository projections, EF mapping, and PostgreSQL.
- `ValidateActiveUserCredentialOnly` is spelled consistently in PostgreSQL, repository interfaces/implementations, handlers, bootstrap SQL, and stored-function references.
- Bulk examples now use Staff Employment Type/Staff Member file names and the `StaffMemberCode`/`StaffEmploymentTypeId` contract.
- Live DB catalog has zero table, column, routine, constraint, or index names containing `tenant` or `employee`.
