## Observed failures and resolution

1. A valid staff create request using a Host-created category returned HTTP 500. PostgreSQL reported `CK_StaffMember_StaffCategoryId`, which restricted IDs to the original range 1–5. The Host-managed catalogue allocated a later ID. The additive migration removes only that obsolete check, requires the catalogue FK to exist and keeps FK enforcement. A guarded rollback refuses to reintroduce the range while extended categories are used by staff.
2. After the constraint correction, staff insertion reached a second HTTP 500: `Nullable object must have a value` in `BaseStaffMemberRepository.CreateStaffMemberAsync`. The new staff person has no Position assignment until its database identity is allocated. Three shared Position read projections now explicitly coalesce a nullable left-join Position ID. The handler resolves response identity after assigning the primary Position and returns the authoritative category name.

No failed attempt left a duplicate sample teacher. A full local PostgreSQL backup preceded the constraint migration. The migration was applied to local only; no Render schema mutation occurred in this continuation.
