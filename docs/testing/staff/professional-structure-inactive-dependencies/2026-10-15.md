# Staff professional structure inactive dependency lifecycle

## Environment and scope

- Date: 2026-10-15
- Environment: local Angular workspace against the configured local API
- Branch: `development`
- Scope: tab dependency order, inactive dependency filtering, historical edit
  visibility, and confirmation-based activate/deactivate actions

## Prerequisites and sanitized example

The institution has an active category named `Teaching Staff` and an inactive
category named `Head Mistress`. A historical Position may already reference
`Head Mistress`. No credentials, tokens, or personal documents are included in
this report.

## Expected behaviour

1. Tabs appear as Job Families, Staff Categories, Capabilities, Duties, and
   Positions.
2. New Position and mapping forms exclude inactive dependencies.
3. Edit forms retain an already selected inactive dependency as a disabled
   option.
4. The default All filter displays active and inactive records.
5. Activate and Deactivate open the established confirmation dialog. Cancel
   performs no mutation; Proceed calls the existing API path.

## Actual result

The Angular implementation now loads complete reference catalogues and derives
context-specific options through one shared rule. Active dependencies remain
enabled. Unselected inactive dependencies are removed. Selected inactive
dependencies remain visible and disabled. The same rule is used for category
job-family mappings and Position category, job family, capability, and duty
inputs. Staff categories, professional masters, and positions share the
existing confirmation-dialog pattern for status changes.
