# Staff canonical routes — 2026-10-11

## Environment and scope

- Environment: local development
- API: Skolenza .NET solution, Release configuration
- UI: Skolenza Angular workspace
- Scope: remove duplicate `/api/Employee...` controller aliases and retain canonical `/api/Staff...` consumers

## Expected result

Swagger exposes only Staff routes for the migrated Staff controllers. Angular service URLs match those routes. Existing authentication and permission behavior remains unchanged.

## Actual result

- Removed 15 `Employee` route aliases from Staff, Staff Employment Type, Staff Reporting Mapping, Campus Assignment, Device Enrollment, Work Arrangement, Work Pattern and Work Mode Override controllers.
- Active Angular services were already using the corresponding Staff URLs.
- Added `InstitutionCompatibilityRouteTests.Staff_endpoint_does_not_publish_employee_alias` cases for every affected controller.
- Focused automated result: 24 passed, 0 failed, 0 skipped.
- Release-generated endpoint metadata contains no `api/Employee` route.

## Persistence and cleanup

This route-only batch does not mutate database rows. The separate physical `Employee` to `StaffMember` database and source-model migration remains a coordinated schema/API/UI batch and must not be represented as completed by this route verification.
