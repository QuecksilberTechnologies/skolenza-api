## Investigation and changes

- Observed gap: collection GET handlers returned unbounded arrays with no page metadata; unit responses embedded all topics.
- Added a shared EF paging helper and central defaults, preserving the existing permission DTO ancestry and `ApiResponse.SuccessPaginated` envelope.
- Wired Frameworks, Units, Topics, Plans, Deliveries and Progress to paged repository overloads. Count and page execute in SQL. Ordering includes a unique Id tiebreaker.
- Added Topics GET through the same StaffMember permission pipeline. No authentication/permission bypass, new business catalogue, schema migration or seed is introduced.
- Paged unit headers omit Topics. Existing single-record Unit saves and plan/delivery write/review projections keep their complete children. Approved progress still reads every applicable coverage record for returned units.
- Two initial new-fixture runs failed before pagination assertions: tracked TPC seed objects shared IDs across entity types, then cloned timestamp values had unspecified DateTime Kind. Fixture reads now use no-tracking, clear temporary tracked batches, and assign valid UTC audit dates. Neither failure was recorded as a pass; no locked EF mapping was modified to accommodate the test.
- Production files: curriculum controller/DTOs/handlers/repository/interface, new `PaginationDefaults.cs`, new `QueryPagination.cs`. New focused tests: `CurriculumPaginationTests.cs`. Existing unrelated uncommitted work was preserved.
