## Investigation and changes

The six Academic tabs share the existing GET `/masters/{masterType}` route.
The new paged permission DTO uses existing `PaginationDefaults`. The handler
returns the existing `ApiResponse.SuccessPaginated` envelope. The repository
pages each typed, scoped EF query through the existing `QueryPagination` helper,
then uses the existing academic projection for dates, parent IDs/names, type,
capacity, level, curriculum version and required periods. Name + Id ordering
provides a deterministic tiebreaker. Internal unpaged reads and single-record
save projections remain intact; no new filters/business rules were added.

Curriculum already had pagination. It required verification, not a duplicate
implementation. Professional and Curriculum code were not changed in this task.
Earlier uncommitted Professional changes were preserved. The central helper,
permission pipeline, entity mappings, seeds and database schema were unchanged.

Changed production areas: Academic DTOs, repository interface, repository,
handler and controller. The existing Academic test fixture was extended.
