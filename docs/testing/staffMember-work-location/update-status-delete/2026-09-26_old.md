# Employee Work Location update, deactivate, and delete — 2026-09-26

## Environment and reported failure

- Backend branch: `main_branch`.
- Angular branch: `development`.
- Reported edit request failed model binding because `employeeId` was numeric while the update DTO
  requires the tenant-salted encoded string.

## Root cause

Create received `employeeId` from the employee dropdown and therefore sent an encoded string.
Employee Location Assignment get-all/get-by-id returned the database `long` in the response DTO.
Edit loaded that fresh numeric value and sent it back to update. ASP.NET rejected the JSON before
the update handler ran: a JSON number cannot bind to the configured string property.

The response DTO and every Employee Location Assignment response mapping now expose the employee ID
as an encoded string using the authenticated tenant salt. Numeric employee IDs remain internal.

## Tested cases

1. Create sends the encoded employee ID unchanged.
2. Update sends the complete replacement body with the encoded employee ID unchanged.
3. Deactivate calls `POST /api/EmployeeLocationAssignment/update-status` with ID and false status.
4. Delete calls `DELETE /api/EmployeeLocationAssignment/delete/{id}`.
5. Read-response contract declares employee ID as string and maps it through the tenant encoder.
6. Update cannot remove primary/attendance/active coverage or shorten dates while an active,
   non-soft-deleted Work Arrangement depends on the assignment.
7. Deactivate and delete use the same dependency guard.
8. Soft-deleted Work Arrangements do not count as active dependencies.
