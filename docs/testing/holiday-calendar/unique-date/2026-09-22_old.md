## Investigation and changes

The previous CRUD check matched location/date/**name**, and the import skipped existing active matches. This allowed another name on the same date and did not treat inactive rows consistently. The repository now finds any non-soft-deleted row by tenant/location/date, irrespective of active state or name. Create/update return a validation message with the existing row Id and active/inactive status. Update and delete can target an inactive nondeleted row by Id; detail GET can retrieve it so the UI can edit it. The list still shows active rows. Import rejects any same-date conflict in the file or DB before saving any row, including inactive DB rows. A partial unique index prevents concurrent writes from bypassing the application check; its unique violation is translated to the validation error. Soft-deleted rows do not occupy the date.
