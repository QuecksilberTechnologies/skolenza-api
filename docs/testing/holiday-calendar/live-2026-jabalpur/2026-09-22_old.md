## Prerequisites and test data

The target DB had no holiday rows and showed one active tenant-8 location, Id 5. The input [CSV](holidays-2026.csv) contains 31 real named holidays with date, optional flag and source/meaning in Description: all 29 holidays in the source's government list, plus two source-listed optional holidays (New Year's Day in January and Guru Purnima in July) so each month has a row. This does **not** import all 63 optional holidays from the source. Sunday/Saturday holidays remain on their actual dates, with weekday noted in Description where relevant. `IsOptional=false` reflects the source's government-list category; it is not a company approval decision. Numeric tenant/location IDs are observed in this DB only.

## Investigation and changes

No API code changed. The calendar was populated directly in the configured PostgreSQL DB using a guarded, repeatable SQL script because an authenticated tenant-8 API session was unavailable. Direct SQL does not validate the API permission pipeline or import HTTP behavior. The insertion verifies active tenant/location and source count/month scope before writing, uses a transaction, and skips matching active records on rerun. The CSV is the exact source data used; no generic test-employee names were inserted.
