## Investigation and changes

The original row duplicated geography (`CountryCode`, `StateCode`) already owned
by `TenantLocation`, stored a redundant `HolidayYear`, used a timezone timestamp
for a calendar date, and had both `Description` and `Remark`. The refactor uses
`TenantLocationId`, derives the year from `HolidayDate`, stores PostgreSQL `date`,
and retains `Description` as the single descriptive field.

The migration aborts if it must introduce a required `TenantLocationId` while
rows already exist. This prevents arbitrary location assignment. It is not run
against the live target before deployment because dropping mapped columns would
make the currently deployed old build incompatible.
