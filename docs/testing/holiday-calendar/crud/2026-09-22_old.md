## Investigation and changes

The old GET handler called an unscoped `GetAllHolidaysAsync` and had no runtime permission check. The controller now routes through tenant-scoped handlers for list, detail, create, update and delete. A dedicated MediatR permission behavior uses the existing authenticated tenant validation, module-code lookup, operation lookup, stored-procedure permission check and `TenantRuntimePermissionValidator`. The old unscoped GET handler was removed. The repository validates active tenant-owned locations, reads only tenant-owned active holidays, rejects duplicate name/date/location combinations and soft-deletes with audit fields. No holiday policy generation or bulk import was added.
