## Environment and build

- API used by that UI: deployed Render API.
- Corrected backend: local `main_branch`, Release configuration.

## Scenario

1. Open Policy 15, Draft Version 16 in Edit Policy.
2. Keep the loaded eight Leave Types, 21 rules and three applicability rows.
3. Enter a non-empty change summary.
4. Select **Save changes**.

Expected: the Draft version is replaced atomically and the updated detail is returned.

Observed before correction: Render returned its generic server-error response with request ID
`0HNP5OC1DOBOI:00000006`. The form remained on the edit route.

## Cause and correction

`UpdateDraftAsync` marked the existing rules, applicability rows and version Leave Type links for
deletion, then added their replacements before the same `SaveChangesAsync`. The old and new graph
reuse version-scoped unique keys such as rule order and Leave Type. PostgreSQL could therefore see
the replacement insert before the old key was released and reject the transaction.

The repository now flushes the removals before constructing the replacement graph. Both database
operations remain inside the existing transaction; partial edits cannot be committed.
