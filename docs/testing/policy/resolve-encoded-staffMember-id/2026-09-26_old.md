## Investigation and changes

- Observed failure: Swagger exposed `EmployeeId` as `integer(int64)`, while Employee list/view returns a non-numeric encoded string.
- Confirmed cause: Resolve DTO used `long` and the Angular dialog attempted `Number(employeeId)`.
- Confirmed encoding behavior: `IdEncoderService.EncodeId_long` and `DecodeId_long` use the application's global static salt. The supplied tenant-key argument does not participate in the current long-ID encoding implementation.
- Change: Resolve now accepts and sanitizes the encoded string, decodes it in the handler, and queries by the internal numeric ID plus authenticated tenant ID. Angular sends the selected encoded value unchanged.
- Isolation: repository lookup retains `TenantId` filtering, so a decoded identifier cannot resolve an employee from another tenant.
