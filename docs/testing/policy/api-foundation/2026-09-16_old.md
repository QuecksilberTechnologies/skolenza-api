# Policy API foundation scenario — 2026-09-16

## Environment and scope

- Environment: local source/build; no deployed API claim.
- Database schema prerequisite: `CreateGenericTenantPolicyFramework.sql` was
  previously applied and verified in the target DB.
- Scope: EF mapping, authenticated permission contract, policy type/policy draft,
  lifecycle, approval stages, resolution, assignment, exception and acknowledgement APIs.

## Expected and actual

Expected: all 16 policy entities map to the existing PostgreSQL schema; every API
request uses dynamic ModuleId/OperationId; tenant identity comes from the token;
draft creation/update is transactional; only documented lifecycle transitions are
accepted; employee operations cannot cross tenant boundaries.

Actual: local solution build passed with zero errors. Focused automated results are
recorded below after execution. No real employee/policy rows were inserted by this
local contract run. No production endpoint was called.

## API sequence covered

1. Lookups and policy type CRUD/status.
2. Policy list/detail and transactional draft create/update.
3. Version clone and submit/approve/reject/publish/archive.
4. Resolve effective policies for an employee.
5. Approval-stage CRUD, role/minimum-approval enforcement and progress reads.
6. Manual assign/remove, assignment list, exception submission/decision/list and
   acknowledgement/list. Assignment creates missing acknowledgement evidence.
7. Document upload/list/delete and policy audit listing.
