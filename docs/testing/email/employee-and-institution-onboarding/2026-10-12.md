## Investigation and changes

- Observed failure: welcome emails were not delivered after institution or staff creation.
- Confirmed cause and evidence: no institution SMTP config exists, so the established Host default fallback was used. The active `WELCOME_EMAIL` template was found. Brevo initially rejected the API machine IP with SMTP status 525. After the user authorized that IP in Brevo, the same application email path returned HTTP 200. The original failure was therefore the provider IP allow-list, not a missing template or rolled-back database transaction.
- A stale local Debug binary initially produced Department/Designation/Role module-code mismatches. Restarting the API from the current Release output applied the already-updated canonical codes and all three permission checks succeeded.
- No application source was changed during this scenario. This report and its README link are the only files added/updated by this verification.
- Limits of the executed verification: SMTP acceptance passed after IP authorization. The user's Chrome/Titan tab was not available to the automation browser, so inbox receipt and rendered content were not independently observed. Deployed Render was not tested.
