## Investigation and changes

- Observed issue: the first adapter build could not resolve `IServiceCollection.AddHttpClient`; provider requests also mutated a shared `HttpClient.BaseAddress` between sandbox and production calls.
- Confirmed correction: added the matching `Microsoft.Extensions.Http` dependency and now construct an absolute URI per request without changing shared client state. Reconciliation/webhook attempt reads no longer depend on the Guardian remaining active after checkout creation. Webhook event IDs are normalized to a fixed SHA-256 representation before database persistence.
- Source behavior: provider order uses the server-calculated installment amount and stable idempotency key. Successful payment is re-fetched from Cashfree and then transaction, receipt, installment and attempt updates are written under the existing serializable transaction. Webhook validates Cashfree HMAC over timestamp plus exact raw body. Three-decimal currency is rejected before provider I/O; no lossy conversion is made.
- Modified/added files: Cashfree client, HTTP dependency registration, Student fee repository, webhook handler, Student provider tests, Student continuation, architecture doc, UI handoff, this report and test index.
- No UI/Angular files, SQL applications, database writes, credentials, or deployment were performed.
