## Investigation and changes

- Observed: admission status/editability was read before a transaction or without a shared row lock. A concurrent request could act on a stale Draft/review state. Document metadata/review and quote creation used the same unsynchronized admission state.
- Correction: admission transitions and edits, admission Guardian link changes, document version/review persistence and fee quote creation acquire the same institution-scoped admission row lock within their existing/new repository transaction, then recheck the relevant state before writing. The initial pre-upload requirement read remains read-only; the persistence step revalidates after locking.
- Changed files: Student registry, document and fee ledger repositories; the Student concurrency database test; current handoff/continuation and scenario records. No schema, permission mapping, Angular or deployment changes were made.
- Limits: these cases prove only the listed interleavings and repository paths. Full approval transaction, other mutable master data, provider behavior, real role grants, authenticated HTTP and deployment still require separate acceptance.
