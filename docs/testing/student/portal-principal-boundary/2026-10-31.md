## Reproduction and correction

`TokenClaimHelper.ExtractClaims` did not copy the signed `UserType` claim into `GetTokenInfoDTO`, and `RequestCommonHelper.ValidateAndExtractClaims` consequently could not forward it. `CommonRequestService.ValidateInstitutionUserRequestAsync` therefore received null and its existing non-staff type check did not execute. Before the correction, an isolated signed synthetic token with a non-staff type and staff-shaped claims reached a mocked active-staff lookup and was accepted by the common validator. This fixture does not establish that an actual issued portal token can access a live staff endpoint; issued tokens, live database identity checks and role grants were not tested in that reproduction.

The existing signed-claim extraction now carries nullable `UserType` through the same DTO and request mapping. The existing validator rejects explicit Host and StudentPortal types before staff lookup. Institution tokens and legacy tokens with no type retain the pre-existing behavior. Invalid signatures and expired tokens remain rejected. No new token issuer or permission path was added.
