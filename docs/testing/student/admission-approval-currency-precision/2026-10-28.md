## Investigation and changes

- Observed gap: Fee arithmetic assumed two decimal places, and approval could create a Student without first checking applicable required-document completion and a saved fee schedule.
- Confirmed cause and evidence: Fee request/response and persistence contracts lacked a precision snapshot. The review path created Student before readiness validation.
- Changed files: currency master, fee DTOs/entities/repository/calculator/EF mapping and additive SQL; admission approval repository source; focused Student tests; continuation, architecture and UI handoff documents. Angular was not changed.
- Behavior: `CountryCurrencyMaster.DecimalPlaces` permits 0/2/3. Active primary campus-country currency is resolved by the API. Structure and quote persist `CurrencyDecimalPlaces`; rounding/payment normalization use the quote snapshot. Approval checks exactly one active primary Guardian, active linked Guardians, latest applicable Student/Guardian document status and expiry, and a fee quote with a matching installment schedule before Student insertion in the existing transaction.
- Limits: Source-level tests do not establish database rollback, lock behavior, schema validity against deployed DBs, S3 operation, or authenticated permission behavior.
