## Investigation and changes

`StudentFeeLedgerRepository` now aliases both scalar lock queries, retries only PostgreSQL serialization failures with the same idempotency key, returns a safe conflict if the bounded retry is exhausted, and reloads the locked installment. New webhook events are marked processed through the tracked entity rather than queried before insertion; concurrent duplicate events are retried after a serialization failure. Its offline and Cashfree payment times, checkout expiry and receipt issue times use UTC represented in the existing timestamp-without-time-zone columns. `SkolenzaDbContext` explicitly maps those columns; same-request payment timestamp comparisons use PostgreSQL microsecond precision. No database migration or Render data mutation was performed. Other timestamp fields and external provider behavior were not validated by this scenario.
