## Investigation and changes

- Observed failure: Portal login becomes available after admission approval, but the existing document endpoints only supported staff-assisted admission uploads. Guardian self-service therefore lacked a post-enrollment document API.
- Confirmed cause and evidence: No portal-authenticated post-enrollment document route/repository flow existed in the current source when this phase began.
- Changed files and commit: Added the portal document repository, handlers, authenticated controller, staff review command route, DI/permission mapping, additive SQL and API contract tests. Updated EF check constraint after the design-model contract test exposed the missing mapping. No commit was created.
- Behavior: Requirements are scoped to the active enrollment campus/session. Guardian access checks the linked active Guardian profile and relationship portal access; Student scope requires the Student persona or an authorized linked Guardian. Uploads use the existing storage abstraction, generated object name, checksum/version metadata, append-only review history and failure compensation. Pending/approved versions cannot be overwritten; rejected/returned versions may be replaced. Download links are short-lived and checked against the exact authorized document. Status values come from the central Student options API.
- Limits of the executed verification: Tests are source contracts. They do not prove PostgreSQL translation/transactions, object-store upload/delete/signing, malware scanning, email, authentication behavior at runtime, role grants, or deployed behavior.
