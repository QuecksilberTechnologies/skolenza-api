## Investigation and changes

The original document list query composed ordering/pagination over a positional record projection that EF could not translate; direct repository execution reproduced the HTTP 500. A SQL-translatable property projection fixes the list and exact-document query. The repository now reuses the existing portal profile check to reject disabled/unverified accounts and requires the same current enrollment for downloads. Guardian uploads validate Guardian ID. Review obtains a PostgreSQL row lock in a transaction before checking state and writing the review and history; the pre-fix forced race saved both decisions. UTC timestamps are mapped to existing `timestamp without time zone` columns and written as UTC clock values with unspecified kind.

Upload persistence now rechecks portal access and the latest version inside a serializable transaction, using database locks and a bounded retry on serialization conflicts. The existing handler deletes the uploaded object when persistence fails. The account- and Guardian-link-revocation and same-version races above were exercised using PostgreSQL and fake storage. External object-storage compensation is not established by those tests. Previously issued signed URLs may remain usable until their expiry.

One intermediate run had 6 failures because a timestamp mapping was accidentally applied to the separate admission-document entity; that mapping was moved to the intended Student record document entities, and the final full suite passed. No admission-document behavior was intentionally changed.

A later test run failed in test cleanup because it attempted to roll back an already committed transaction; the cleanup was corrected, and the full suite passed with both Guardian-link race orderings.
