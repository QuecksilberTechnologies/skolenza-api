## Investigation and changes

- Observed: the admission detail request had only an ID. `StudentPermissionBehavior` extracts permission metadata from request properties and therefore rejected it before the handler, regardless of a caller's permissions.
- Correction: the controller binds the existing `PermissionRequestDTO` from query parameters and forwards it with the admission ID through MediatR. The existing behavior retains module, operation and role checks.
- Observed: Cashfree reconciliation calls `RecordCashfreePaymentAsync`, which can write ledger and receipt state, while its behavior mapping required only View.
- Correction: reconciliation requires the existing `STUDENT_FEES` Update operation. The UI must resolve that operation dynamically; no numeric permission IDs were seeded or hardcoded.
- Changed files: Student controller, Student request record, Student permission behavior, Student tests, UI handoff, local Word copy and continuation. No commit or deployment.
- Limits: these tests use test doubles for permissions and provider calls; they do not prove authenticated HTTP, live role grants, tenant isolation over HTTP or Cashfree settlement.
