## Investigation and changes

The staff fee APIs required staff permissions; the Guardian portal lacked fee routes. Added portal-scoped reads and checkout, reusing portal profile checks, the fee ledger and staff Cashfree operation. Checkout now locks the Student, portal account, relevant Guardian/link rows and admission before rechecking existing portal authorization and installment ownership within the same serializable transaction that creates or resumes the attempt. A checkout already authorized at the attempt commit may finish its provider request after access is revoked; later checkout requests are denied. An initial protected-test command accidentally passed a connection string where the test expected a settings-file path; that setup run failed. Re-running with the correct settings path passed 41/41. A later reverse-race test initially failed because its fixture committed an already completed test transaction; the fixture was corrected and the full suite passed. Neither was evidence of a product regression.
