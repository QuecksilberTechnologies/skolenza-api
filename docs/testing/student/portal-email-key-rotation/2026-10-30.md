## Investigation and changes

The existing Student v1 envelope uses the currently resolved institution key and contains no key identifier. Prior data cannot be decrypted after an uncoordinated key replacement. Bank uses unauthenticated AES-CBC, so blindly trying historical keys until decryption succeeds cannot prove correctness. Separate process caches can retain a key independently, while legacy bearer claims carry the key used by existing Bank code. A safe complete design must control old tokens and in-flight writes, re-encrypt or otherwise explicitly version legacy records, preserve old Student envelopes and prove rollback across all consumers. No application logic or actual key was changed in this scenario.

Source inspection also found `EncodeString` and `DecodeString` use different salt selection in the existing `IdEncoderService`; no application call sites for those methods were found in the inspected source. This is not demonstrated as a live Student defect and was not changed.
