# Multi-installment offline batch schema foundation — 2026-11-03

WIP. `database-scripts/AddStudentFeePaymentBatch.sql` creates an idempotent
batch header and links to existing installment payment transactions. Composite
foreign keys bind the batch, selected installment and linked payments to the
same institution and quote. A batch has one linked payment per installment;
a payment cannot belong to two batches. Existing payments are not backfilled.

The script ran twice against the guarded disposable Local database. A synthetic
SQL transaction linked an existing test payment, rejected a duplicate link and
rejected selection of an installment from another quote; all probe writes were
rolled back. These checks do not test tenant isolation in every path, payment
posting, concurrent idempotency, retries, HTTP authorization or receipts.

This script has **not** been applied to Local or Render application databases.
Batch and item entity/EF mappings were added in source, including composite
tenant/quote relationships. The model mapping test checks all five named foreign
keys; focused fee tests passed 25/25 after recompilation. The prior full Student
gate passed 180/180, protected gates 91/91 and 41/41 with these model mappings;
the subsequent change added mapping assertions only. There is no
handler, permission mapping or batch API yet. Payment
amount reconciliation, full rollback on failure, policy enforcement,
consolidated receipt, reversal, real provider testing and deployment remain
pending. No payment was collected and no Angular work was performed.

Before this WIP, protected Student **180/180**, security/profile **91/91** and
staff/rollback **41/41** were recorded in the prior checkpoint. After this
SQL-only scratch change, those gates passed again: **180/180**, **91/91** and
**41/41**, without skips.
