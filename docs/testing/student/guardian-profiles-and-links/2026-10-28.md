## Investigation and changes

- Observed gap: Guardian and StudentGuardian tables existed in schema/model, but no API surface managed profiles or links; guardian relation values were not exposed to UI.
- Confirmed cause: route and command inventory had no Guardian handlers; no relationship enum was defined.
- Changes: added institution-scoped paged Guardian directory and profile create/update, per-Student link list/create/update/close, central relationship enum/options, permission mappings, normalized-email conflict check, active primary Guardian check, and matching EF/SQL uniqueness/range constraints. Closing a link preserves it, sets an effective end date, and disables relationship portal access.
- Limits: this does not create portal credentials or verify contact ownership. Admission drafts do not yet carry Guardian data, and approval is not yet atomic with Guardian links/documents/fees.
