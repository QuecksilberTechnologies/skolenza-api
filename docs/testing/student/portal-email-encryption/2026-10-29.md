## Investigation and changes

- Invitation and reset placeholder JSON previously contained token-bearing URLs in cleartext in `EmailQueue`. New Student portal messages now store an authenticated AES-GCM envelope using the institution key; the background worker decrypts it for delivery. Gateway and portal encryption use different authenticated purposes. Other email formats and legacy queued Student messages retain their existing processing path.
- The Local queue had zero existing Student portal invitation/reset rows when checked; no existing queue data was rewritten. Other environments were not checked or migrated in this scenario.
- Active-key rotation while a message is queued can make its ciphertext unreadable: the existing resolver has no key-version lookup. This is not yet resolved. Access and retention of legacy plaintext messages in other environments must also be reviewed.
- Local reset template was inserted idempotently; sender remains from existing SMTP configuration.
