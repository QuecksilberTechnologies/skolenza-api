## Investigation and changes

- Observed gap: the API had a paged admission list and write/review operations, but no single-admission detail read or status-history read for UI clients.
- Confirmed cause and evidence: `StudentAdmissionsController` exposed list/create/update/review routes only; `StudentAdmissionStatusHistory` existed as persistence/audit entity without read routes.
- Changed files and commit: Added DTOs, repository methods, institution-scoped handlers, View permission mappings, routes, and source contract assertions. Updated the UI handoff and continuation documentation. No commit was created.
- Detail route: `GET /api/Student/admissions/{id:long}` returns the existing admission response, including current status and Student ID/code after approval. Missing or out-of-institution records use the standard 404 response.
- History route: `GET /api/Student/admissions/{id:long}/status-history?pageNumber=1&pageSize=10` returns paged transition audit in chronological order. The initial Draft event exposes nullable `fromStatus`; subsequent values use `StudentAdmissionStatus`. Response includes reason, actor ID and change timestamp.
- Limits: tests verify source contract, not actual PostgreSQL query translation, tenant isolation, response envelope, or HTTP permissions.
