## Investigation and changes

- Observed failure: none; this is a new API/security slice.
- Confirmed design: use school-owned merchant credentials, separate from Host subscription billing. AES-GCM service uses random nonce, 128-bit tag, version marker, SHA-256-derived institution key and institution-bound associated data. Existing Staff bank encryption is unchanged.
- Added authenticated `GET/POST/PUT /api/student/fees/gateway-configuration`, institution-scoped config entity/EF mapping/repository, central Sandbox/Production enum exposure, and additive SQL `database-scripts/CreateStudentCashfreeGatewayConfiguration.sql`.
- Read response DTO exposes only masked ClientId and booleans indicating whether secrets exist. No secret is returned.
- Changed files are uncommitted; no commit was created.
- Limits: key-source choice is awaiting user confirmation because replacing an institution's active key would invalidate stored ciphertext unless secrets are re-encrypted. Cashfree order creation, payment reconciliation, webhook, ledger/receipt transaction and provider sandbox remain unimplemented.
- Current official Cashfree [Create Order documentation](https://www.cashfree.com/docs/api-reference/payments/latest/orders/create-order) specifies at most two decimal places for order amounts; fee quotes may have three decimal places. No lossy rounding behavior was added. Checkout rules for three-decimal currencies remain pending.
