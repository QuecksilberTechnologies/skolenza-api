## Scenario

Create independent singular Tenant Department, Tenant Designation, and Tenant
Role root navigation parents while migrating the existing leaf codes in place
and preserving their IDs, PageName values, routes, and dependencies. Ensure a
new Tenant Admin receives the leaf permissions through tenant creation, and an
existing Tenant Admin receives only missing grants through Host entitlement
synchronization.

## Expected hierarchy

```text
TENANT_DEPARTMENT (root; ParentModuleId NULL)
└── DEPARTMENT (tenant-departments)

TENANT_DESIGNATION (root; ParentModuleId NULL)
└── DESIGNATION (tenant-designations)

TENANT_ROLE (root; ParentModuleId NULL)
└── ROLE (tenant-roles-permissions)

EMP_MGMT (existing root)
└── EMPLOYEE_TYPE (tenant-employee-types)
```

Parents are independent, non-leaf navigation roots with no operation mappings. Operations
remain on the existing leaf modules.

## Duplicate and permission expectations

- One parent module per `ModuleCode`.
- One plan mapping per `SubscriptionPlanId + ModuleId`.
- Tenant creation reads the active plan mappings and creates enabled hierarchy.
- Tenant Admin grants are created only for leaf operations.
- Host entitlement synchronization inserts only missing enabled rows and Tenant
  Admin grants; it does not duplicate or overwrite an existing grant.
