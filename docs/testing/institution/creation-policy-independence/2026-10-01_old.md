## Investigation and changes

- Observed failure: Tenant registration still staged two legacy, system-generated policy types. One local edit had already removed the Insurance policy name, which would leave an invalid incomplete entity at runtime.
- Confirmed cause and evidence: `CreateTenantCommandHandler` called the single-use `AutoCreatePolicyTypesAsync` method. The new framework requires a policy type code/category supplied by the tenant policy flow, while the tenant-registration records supplied neither. The documented lifecycle creates the tenant/admin first and policy types afterward.
- Suspected cause / remaining uncertainty: None for the source-level dependency. Deployed behavior remains unverified until the corrected build is deployed.
- Changed files and commit: tenant handler, policy repository contract/implementation, constants and Host regression test; uncommitted working tree.
- What the executed regression tests establish and do not establish: The tests establish that both public and Host tenant creation paths preserve success, save-failure rollback and post-commit email-failure behavior without calling the removed method. They do not establish deployed HTTP behavior or direct database row counts.
