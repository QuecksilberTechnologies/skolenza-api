## Investigation and changes

- Observed failure: a direct SMTP message succeeded at 09:02, while the deployed Host resend failed around 09:06, creating the appearance that the same flow worked intermittently.
- Confirmed cause and evidence: these were different caller paths. The successful diagnostic originated outside Render. The application request originated from Render, whose service can use any address in its configured outbound CIDR ranges. Brevo SMTP-key blocking was active, but only individual observed IPs had previously been authorized. Depending on the selected Render egress address, authentication could pass or be rejected before a transactional event was created.
- Configuration correction: the Render secret setting name was restored to `EmailConfig__Secret`, the latest build was deployed, and the complete Render ranges `74.220.48.0/24` and `74.220.56.0/24` were authorized in Brevo.
- Diagnostic rule for recurrence: do not treat a successful workstation SMTP smoke test as proof that Render can send. Compare caller environments, inspect Brevo's **Unauthorized IP addresses** tab, copy the complete current list from Render **Connect > Outbound**, and authorize every CIDR. A single observed Render IP is insufficient.
- Security rule: retain SMTP blocking only when every Render outbound range is authorized. If Render changes the listed ranges, update Brevo before relying on the new range. Do not store SMTP keys in test reports.
- Changed files and commit: documentation only in this run; commit pending.
- The deployed UI success proves that the API accepted the resend after the CIDR correction. Inbox delivery and a matching post-fix Brevo Sent/Delivered event were not independently captured in this run.
