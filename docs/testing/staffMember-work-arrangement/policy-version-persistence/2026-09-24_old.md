## Investigation and changes

- Confirmed cause: the dropdown returned `policyVersionId`, while the form mapped a nonexistent legacy ID and submitted `0` as `attendancePolicyId`.
- The backend's combined validation condition then returned a Hybrid configuration message even though the failing value was the policy ID.
- Create/Update now accept and validate `PolicyVersionId`. Validation checks Tenant, `ATTENDANCE` category, active/non-deleted type and policy, active `PUBLISHED` version, and the version effective window against the Work Arrangement start date.
- Validation messages are separated so an invalid policy version cannot surface as a Hybrid-type error.
- The Angular form stores and submits the returned `policyVersionId`; it sends `hybridType` only for Hybrid work.
- The migration retains nullable legacy `AttendancePolicyId` for historical rows and performs no guessed backfill.
